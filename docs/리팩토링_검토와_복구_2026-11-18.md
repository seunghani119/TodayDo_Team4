# TodayDo 리팩토링 검토와 복구 기록

## 검토 기준과 결론

이 기록은 2026년 11월 18일 대화에서 확정한 방향을 기준으로 합니다.

**일정 입력 → DB 저장 → 지도 장소에 맞는 실제 기상청 예보 → Claude가 원문과 예보를 직접 읽고 조언 → 화면 표시**

현재 소스는 이 방향과 일치합니다. 사용자 제목과 내용을 키워드로 분류하거나 고정된 활동 적합도를 계산하지 않습니다. 정상 AI 답변을 숫자 필터로 걸러 기본 안내로 대체하지도 않습니다. 예보가 일부이거나 없어도 원문과 해당 상태를 AI에 전달합니다.

기존의 일정 등록·수정·삭제, 지도 선택, 날짜 검색, 저장하지 않은 편집 확인, 실행 중 30분 날씨 갱신 기능은 유지했습니다. 모델, 서버 주소, DB 구조와 사용자 데이터는 변경하지 않았습니다.

## 무엇을 왜 정리했는가

| 파일 | 바뀐 점 | 이유 |
|---|---|---|

| 서버 Services/KmaForecastService.cs | 기존 기상청 통신·페이지·시간별 항목 묶기를 이동한 파일 하나 추가 | 기상청 응답 처리와 일정 API 처리를 따로 이해할 수 있게 함. 새로운 판단 로직은 아님 |
| 서버 Program.cs | 기상청 서비스를 30초 제한의 HTTP 서비스로 등록하고 깨진 주석 수정 | 생성과 연결 설정을 시작 지점에 모음 |

| 클라이언트 Services/ApiService.cs | 성공 확인·JSON 읽기·빈 응답 검사를 공통 메서드로 통합 | 244줄에서 199줄로 줄이고 엔드포인트마다 반복하던 처리를 한곳에서 관리 |
| 클라이언트 MainWindow.Details.cs | 생성자를 한 번 호출하기만 하던 중간 메서드 제거 | 동작 없이 이동 단계만 늘리던 코드를 줄임 |

### 응답 처리에서 보완한 점

- 지역 미선택·과거·예보 대기의 응답에도 공통 일정 원문, 식별자, 확인 시각을 넣습니다.
- 날짜는 손실 없는 ISO 문자열로 전달해 JSON 노드의 날짜 해석 차이를 피합니다.
- 날씨와 AI 요청은 오류 본문을 읽을 때도 취소 토큰을 전달합니다.
- AI 서버 오류도 message/detail/title을 우선 표시합니다. 본문이 없으면 다른 API와 같은 공통 HTTP 오류 문구를 사용합니다.

## 검증 결과와 한계

- 외부 HTTP와 DB를 대체한 회귀 검사 35개 통과.
- 일정 제목·내용 원문 전달, 실제 예보 전달, 네 가지 예보 제한 상태 전달 확인.
- 기상청 다음 페이지 조회와 시간별 항목 결합, 범위 밖 예보 제외 확인.
- 연장 예보의 강수 코드 해석, 날짜 정밀도와 null 종료 시각 확인.
- 서버 서비스 생성, HTTP 오류, 요청 취소, 빈 AI 답변 검사 확인.
- 최종 Debug 및 Release 전체 빌드 모두 경고 0개, 오류 0개로 통과했습니다.

미술관·걷기 등은 검사 프로그램 안의 합성 입력입니다. 실제 사용자 일정으로 추가하거나 DB를 수정하지 않았습니다. 이번 작업에서는 실제 Claude·기상청 외부 호출과 WPF 화면 직접 조작을 하지 않았습니다. 따라서 빌드와 검사가 성공해도 외부 API의 현재 가용성과 생성 답변의 품질까지 보장하는 결과는 아닙니다.

## 언제든 이전 상태로 복구하는 방법

작업 시작 전 파일 100개를 보관했고, ZIP 내부의 각 파일을 SHA256으로 원본 목록과 대조했습니다.

- 복구본: `.refactor-backups/20261118-094217/before.zip`
- 원본 해시: 같은 폴더의 `before-manifest.json`
- 이 작업에서 변경·추가한 파일: `changed-files.json`
- 복구 도구: `restore.ps1`
- 최신 복구본 위치: `.refactor-backups/LATEST.txt`

프로젝트 폴더의 PowerShell에서 아래 명령은 복구할 파일 목록만 보여줍니다.

```powershell
& '.\.refactor-backups\20261118-094217\restore.ps1'
```

현재 프로그램과 서버를 종료한 다음, 실제로 되돌릴 때만 다음 명령을 실행합니다.

```powershell
& '.\.refactor-backups\20261118-094217\restore.ps1' -Apply
```

복구 도구는 변경된 기존 파일을 원본으로 돌리고, 이 리팩토링에서 추가한 파일을 제거합니다. 다른 파일은 건드리지 않습니다. 복구 직전의 해당 파일도 별도 ZIP으로 보관하고, 복구한 파일의 해시를 검사합니다. 실제 작업 폴더의 복구는 실행하지 않았습니다. 별도 복사 폴더에서 복구 도구를 실행해 원래 해시 복원과 새 파일 제거를 확인했습니다.

대화에서 “11월 18일 리팩토링 전으로 복구해줘”라고 요청해도 이 기록과 복구본을 기준으로 되돌릴 수 있습니다. 복구본 폴더를 유지해 주세요. 기존 ZIP에는 로컬 설정 파일도 포함되어 있으므로 공개 저장소나 발표 자료로 올리지 않습니다.

복구 후에는 솔루션을 다시 빌드하고 실행해야 합니다. 복구 스크립트는 DB·외부 서비스 데이터나 실행 중인 프로세스를 되돌리는 기능이 아닙니다.
